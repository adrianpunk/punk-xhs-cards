# 内页转换与发布文案

## 原文读取

完整读取清理后的 Markdown，包括各级标题、正文、引用、代码、图片、图片说明和结尾行动建议。作者标注已经用于封面，不放入内页。逐项检查 `parse_markdown.py` 返回的图片清单，不因 alt 为空而跳过图片。

提取：

1. 核心问题与目标读者；
2. 一句话结论；
3. 关键步骤、判断标准和例子；
4. 风险、边界和误区；
5. 读者可以完成的第一步。

同时建立关键图清单：图片索引、对应段落、用途、建议卡片页和可靠图注来源。步骤截图、流程/架构图、数据图表、前后对比、结果或验证证据优先保留；装饰性头图、头像、表情、重复封面、无关 Logo 不进入内页。

教程文章额外建立“步骤—截图—完成标志”映射。凡是让读者确认点击位置、输入内容、选项状态、命令输出或操作成功结果的截图，均视为必备步骤图。

## 默认九张内页

封面是独立无页码图片。默认再生成 9 张内页：

| 内页页码 | 任务 |
|---|---|
| 01 | 定义与背景 |
| 02 | 核心判断框架 |
| 03 | 准备工作或输入 |
| 04 | 方法步骤一 |
| 05 | 方法步骤二 |
| 06 | 核心细节或模板 |
| 07 | 测试与验证 |
| 08 | 风险、误区与边界 |
| 09 | 总结与行动 |

根据文章结构调整 02–08。原文较短时减少内页；原文复杂时增加内页。不要重复内容凑数量。

教程模式不受默认九张内页限制。先保证步骤完整、顺序正确和截图可读，再决定页数；不能为了凑成 9 张内页删除必备截图。

关键图不必机械对应固定页码。图片与其解释放在同一页；若缩到可用区域后细节无法辨认，给它单独一页并减少文字。默认每页最多一张关键图，每张关键图只出现一次。

## 页码

- 封面不显示任何页码。
- 第一张内页显示 `01`。
- 内页页脚显示 `01 / 09` 这类编号；分母只统计内页。
- 输出文件为 `cover.png`、`card-01.png`、`card-02.png`……

## 压缩边界

- 保留观点、因果、条件和限制词。
- 删除重复铺垫和同义句，不删除影响结论的前提。
- 不编造数据、案例、工具能力、个人成绩或平台规则。
- 每页一个核心标题，正文优先 100–240 个中文字符。
- 复杂内容拆成编号项；每项标题 4–12 字，解释 18–45 字。
- 代码只保留必要命令；长代码拆页或改为结构说明。
- 图片承载的信息不能只改写成文字后删图；图片与文字重复时可以缩短文字说明。
- 教程步骤标题使用动作表达，如“创建仓库”“运行验证”“检查输出”；截图紧跟对应动作，不跨页错配。
- 图注只取原文 alt、相邻图注或明确的正文语境，不猜测看不清的数值和界面细节。
- 最后一页给出行动，不重新堆全文。

## 发布文案

生成 `publish-copy.md`：

- 一个推荐标题和三个备选标题；
- 一段自然中文正文，包含共鸣开场、内容说明、收益和行动引导；
- 6–10 个直接相关 tags。

标题把搜索词放在前半句，不使用夸张词，不承诺原文未证明的结果。正文保持作者的第一人称实践感，不伪造经历。

## 交付检查

- 所有专有名词与原文一致。
- 正文提到图片数量时必须与实际交付一致。
- 封面标题可以与发布标题互补，不必逐字相同。
- tags 不蹭无关人物或事件。
- 输出文本可直接复制，不夹带内部说明。
