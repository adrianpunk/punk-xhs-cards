# Markdown 关键图处理

## 目标

保留“没有这张图，读者会难以理解步骤、结构、证据或结果”的图片。不是把 Markdown 中的全部图片原样搬进卡片。

## 建立图片清单

运行：

```bash
python3 scripts/parse_markdown.py <source.md>
```

`images` 为按原文顺序编号的图片清单，包含行号、alt、源地址、本地解析路径、前后文和 `selection_hint`。`selection_hint` 只做初筛：

- `keep`：上下文含截图、流程、图表、结果、验证等信号；
- `skip`：重复图或上下文明确说明是头像、Logo、封面、装饰；
- `review`：必须查看图片并结合全文判断。

即使 alt 为空，也要检查图片。图片可能在下一行才有斜体图注。

## 选择标准

选择：

- 操作流程中读者需要对照的界面或终端截图；
- 展示结构、关系、顺序的流程图或架构图；
- 支撑结论的数据图表、结果截图或验证证据；
- 前后对比、输入输出和关键成品；
- 正文明确引用并解释的图片。

排除：

- 文章头部的横版装饰封面，除非正文把它当案例讲解；
- 作者头像、表情、二维码、无关 Logo 和纯装饰插画；
- 内容相同的重复图片；
- 无法读取且原文没有可靠说明的图片。

## 教程模式

文章出现连续步骤、命令以及界面/终端截图时，建立按原文顺序排列的步骤图映射：

| 图片 | 对应步骤 | 类型 | 完成标志 | 是否必备 |
|---|---|---|---|---|
| 图片索引 | 点击、输入、选择、运行等动作 | `instruction` / `checkpoint` / `result` | 用户应看到的界面或输出 | 是/否 |

- `instruction`：告诉读者点哪里、输入什么或如何配置，必备。
- `checkpoint`：告诉读者操作成功后应该看到什么，必备。
- `result`：展示最终效果；若它承担验证作用则必备，否则结合篇幅判断。
- 同一操作的重复截图只保留信息最完整的一张。
- 不把非相邻步骤和截图强行合并，也不打乱原文顺序。
- 必备步骤图多于默认内页容量时增加页数；固定 10 张不是上限。

## 收集选中的图片

图片索引确认后运行：

```bash
python3 scripts/collect_markdown_images.py <source.md> <文章目录/assets/article-images> --indexes 2,4,5
```

脚本会复制本地相对/绝对路径图片，或下载 HTTP/HTTPS 图片，并生成 `manifest.json`。不要把未选图片下载进交付目录。

远程下载失败时，保留源 URL 和图片索引，说明缺失；不要生成一张替代图冒充原图。必要时请用户重新上传原图。

## 卡片编排

- 每张关键图只出现一次，默认每页最多一张。
- 图片与解释它的段落放在同一页。
- 图片优先保持完整比例，不拉伸、不压扁、不裁掉关键信息。
- 细节密集的图使用 420–520 高度或单独成页；简单示意图可用 260–360。
- 带小号按钮、菜单和终端输出的步骤图优先使用 520 高度；仍不可读时单独成页，减少同页文字。
- 默认不裁剪截图；只允许去除大块空白边缘，且不能裁掉窗口标题、按钮、路径、报错或完成标志。
- 图注只使用 alt、相邻图注或正文中明确可验证的描述。
- 人物仍位于右下页脚区；图片内容不得与人物重叠。
