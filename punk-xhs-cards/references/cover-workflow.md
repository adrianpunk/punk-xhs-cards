# Markdown 到书封面

## 目录

- 元数据解析

- Hero 图
- 书封版式

## 元数据解析

运行 `scripts/parse_markdown.py`，不要凭文件名猜标题或作者。

标题优先级：

1. YAML frontmatter 的 `title:`；
2. 第一个 `# 一级标题`。

作者优先接受靠近文末的独立行：

```markdown
作者：张三
```

```yaml
author: Zhang San
```

从文末向上查找第一个匹配项。为兼容长文导出，也接受文末 `# 关于作者` 或 `# 作者简介` 小节，并取其下一条非空行中第一个 `｜` 前的名字。提取后从内容正文中排除作者标注或整个作者小节。作者缺失时询问用户；不要用角色名、账号、目录名或文章主题代替。

## 封面标题

完整阅读文章后给出一个封面标题。优先保留原题；只有原题冗长、搜索词不清或平台表达弱时才优化。

- 保留核心对象、动作、因果和范围。
- 允许删除重复修饰和平台残留。
- 不添加原文没有的数据、收益或承诺。
- 书名排版优先一行；低于可读字号时最多自然换成两行。
- 不为了排版把一个完整短语强制拆成三行。

## Hero 图

直接使用 `references/hero-image-prompt.md`，不要调用 `punk-cover`。

从文章提取：

- 主题真正表达的关系、变化、动作或结果；
- 一个核心动作，如汇聚、对齐、折叠、连接、推进、拆解、穿透、转化或生长；
- 一个单一的抽象装置隐喻；
- profile 的强调色和深强调色。

生成要求：

- 16:9 横图；
- 暖白编辑背景；
- 石墨黑/炭灰结构；
- 唯一彩色材质来自 profile 强调色；
- 无文字、数字、Logo、水印、人物或伪文字；
- 不生成多个方案或拼图。

Hero 失败时只针对一个问题重试，例如“移除文字”“改为 16:9”“保持单一视觉中心”或“把绿色替换成 profile 强调色”。

## 书封版式

封面由渲染器确定性合成，图像模型只负责 Hero。

- 左侧使用深强调色书脊。
- 顶部大面积放置 Hero，完整 aspect-fit，不拉伸。
- 中部白色书名页覆盖到下部强调色区域；底边必须使用明显的不规则切角：左侧白色向下延伸，右侧强调色提前上升，中间以一个宽而克制的大斜面连接。不要使用贯穿全宽的水平矩形分区，也不要堆叠多个锯齿。
- 标题使用深色无衬线粗体并完整显示。短标题横排一行；长标题若单行字号低于舒适阅读尺寸，按冒号、标点或语义停顿自动平衡成两行并放大，不为坚持单行留下大面积无效空白。
- 作者位于标题下方，来自 Markdown 文末标注。
- 下部使用深强调色，账号在左下，使用半粗体和字距形成出版标识感。
- 不显示品牌名、封面栏目、封面页码或总页数。
- 个人 IP 位于整页右下，保持自然比例。

## 确认门

先展示：

1. 16:9 Hero；
2. 1080×1440 完整封面；
3. 解析到的标题、作者和账号。

只询问“确认还是修改”。用户确认前不得拆分或渲染内页。
